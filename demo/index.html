Try Issuegraph

A pretend issue tracker, running in this browser tab. It works out what to work on next, and why, from the way the issues depend on each other.

Nothing here is real. No sign-in, no server, nothing saved. Change whatever you like — reload the page and it all comes back. Under the hood it runs the real @issuegraph/viewer and @issuegraph/editor packages, unchanged.

Set up a situation. Each row below fakes something a real tracker would decide for you. Change one, then look at the panel underneath to see how it copes.

Colors

The two color sets the viewer ships with. Switching them changes color only. Nothing moves, and nothing is redrawn.

Middle panel

What the big panel in the middle draws. Order map runs the work order down the center, with the issues that explain that order on the left and the ones nobody will work on the right. Sub-issue tree drops all that and stacks big issues with their parts underneath them.

Connection

Fakes a problem between the tracker and this page, so you can see how the panel says so. It does not change the issues — a repo can be mid-import or unreadable whatever its backlog holds. Retry and Review pick order only put it back to Working: there is no real tracker here to re-read, so that is the one honest thing they can do.

Backlog

Which pretend backlog is loaded. Small sample is the hand-built one the page starts on: fifteen issues, one of every kind of link, so you can see the whole idea at a glance. Big backlog is a few hundred generated issues — the map gives up and draws groups instead, the list scrolls, and the audit finds real problems. Fresh repo is day one: forty-eight issues and not one link declared between them yet, so the order comes from your priority labels alone.

Choose what the pretend tracker says to your next edit, then make one. It only happens once and then goes back to accepting, so the retry it offers can actually work.

What you are looking at. On the left, the order to work in — top one first. In the middle, why that order: the lines between issues are the links that set it. On the right, the details of whatever you click.

How much of this page is the packages. The order is worked out by @issuegraph/derive, not by this page: the store takes the ordering code as a plug-in part with no fallback, and this page plugs in the published one rather than writing its own second version of the rules. The list, the map and the details panel are all @issuegraph/editor’s; this page just listens for what they report and draws them again. What is left for a host to supply is what the spec says a host supplies — which issues a worker already has, how many can run at once, the wording, and the colors. Both color sets are the viewer’s own, redeclared, and nothing more.
