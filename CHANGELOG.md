# Changelog

Releases are recorded here. While the spec is a pre-1.0 draft, drafting churn lives in git history, not in version bumps — the version moves when there is a consumer-visible reason for it to move.

## Unreleased

- **SPEC 0.3.0 — a reference is an OPAQUE TRACKER-SCOPED IDENTIFIER (§4.2).** §4.2 previously defined a reference as an integer and said, in as many words, that *"no other identifier type exists in the format"*. That excluded Jira's `ABC-123` and Linear's `ENG-456` by construction, so a specification for machine-readable work relationships could not describe two of the three trackers most likely to use it. A reference is now any tracker identifier, with an optional `#` sigil and an optional `owner/repo` qualifier; `123` and `#123` denote the same issue and parse identically. The numeric shape keeps one bound — a positive, canonically-spelled, exactly-representable integer — not as arithmetic but because a value outside it comes back from a re-render spelled `1e+21`, which no reader accepts. `priority` is untouched and remains an integer 0–3.
  - **Breaking for consumers:** `IssueRef.number: number` is now `IssueRef.id: string`, and `NodeInput.number: number` is now `NodeInput.id: string`. The field is RENAMED rather than widened so every consumer breaks at compile time — a widened `number | string` leaves arithmetic on it compiling, and the order comparator subtracts two of them, which would silently yield `NaN` and an unspecified order for a non-numeric identifier.
  - **§4.2 now records that `#`-sigil references MUST be quoted**, with the failure that makes it normative rather than advice: unquoted in a flow sequence is a parse error, but unquoted in a BLOCK sequence parses successfully to `[null, null]`, with no error and no warning. An issue whose blockers silently vanished reads exactly like an issue with no blockers.
- **The reader delegates tokenizing to a maintained YAML parser.** `@issuegraph/reader` now parses with `yaml` (its first runtime dependency — zero transitive dependencies, `node >= 14.6`, comfortably under the `>=18` floor this package publishes) instead of a hand-rolled restricted-subset reader. §4.1 always required *"a plain YAML data parser"*; this makes the implementation match the rule. **Closes [#6](https://github.com/autnmy/issuegraph/issues/6)** by removing its premise rather than adjudicating it — a hand-rolled grammar for an open format yields one finding per review round indefinitely, and #6 and #10 were two instances of that one class.
  - **Safety is `parseDocument` plus a refusal on warnings, not `parse`.** With `customTags: []` an anchor raises, but an unresolved custom tag does NOT — `!!python/object 1` comes back as the string `"1"` with only a warning, so `parse` alone satisfies §4.1's anchor clause and silently fails its tag clause. Anchors are refused structurally, because `maxAliasCount` is a materializing option and cannot express the rule at parse time.
  - **Diagnostics improved rather than regressed.** A structural refusal now carries the parser's own message, which names the line, the column and the rule.
  - **The hand-rolled line grammar is gone.** `readMappingEntry`, `topLevelKeyScalar` and `stripComment` are removed from the public surface; `locateSection` replaces them, computing each entry's line span from the same document the parse reads, so an editor and a parser can no longer disagree about what an entry is. `isSectionHeader` replaces the strict header predicate. `locateBlock` and the fence patterns STAY — §4.1's canonical-block rule (first `---` block carrying the key, seen through a fence and a banner) is this specification's, not YAML's, and no frontmatter library implements it.
  - **A quoted reference is taken as written.** YAML already strips surrounding whitespace from a plain scalar, so a trim in the reference parser could only ever act on a QUOTED one — where the author explicitly asked for those bytes. `" #123 "` is refused rather than read as `123` and re-rendered as `"#123"`, which would silently change what the author wrote.
  - **`issuegraph: null` reads as an empty declaration, exactly as a bare `issuegraph:` does.** They are the same YAML value — both materialize to `{issuegraph: null}` — so the parser treats them identically rather than distinguishing two spellings of one value by reaching into the syntax tree. `locateSection` still refuses the written form, because inserting a child under a scalar value is invalid YAML: that is a fact about line-based EDITING, not about meaning, and a writer must prepend instead.
  - **Behaviour deltas, all in the refusing direction.** A duplicate key — the `issuegraph` key itself, a recognised field, or an unrecognised one — now refuses the block instead of letting the first or last win silently. An empty flow-list entry (`[,]`, `[1,,2]`) refuses the block instead of yielding a partial list. A structurally invalid section refuses rather than dropping one field. One delta goes the other way: an inline flow mapping on the key (`issuegraph: {priority: 1}`) is ordinary YAML and now READS, where the hand-rolled subset refused it.
- **`@issuegraph/writer`: the default written block is bare, blank-line-terminated, and auto-links.** `renderFrontmatter`'s `fenceWrapped` now defaults to `false`, refs render as quoted `"#123"` / `"owner/repo#123"`, and the block carries a blank line before its closing `---`. Measured against a live markdown renderer: that form renders as rule / paragraph / rule and auto-links every reference, where the previous fenced bare-integer output rendered neither. Auto-linking stamps a cross-reference on the TARGET issue, which is the only surface anywhere showing what an issue is blocking — §4.3.1 has no `blocks` field. The fenced form is still emitted on request and still parses; existing bodies are not migrated.


- **Packages workspace.** The repository is now a pnpm workspace publishing `@issuegraph/*` to npm, with CI that typechecks, builds, tests and enforces isolation, and a publish workflow that runs on an explicit GitHub release.
- **`@issuegraph/core` 0.1.0** — the specification's vocabulary as frozen constants and derived types. Its tests read SPEC.md §4.3 directly, so a field added to the spec and not to the package fails the build.
- **`@issuegraph/reader` 0.1.0** — `parseFrontmatter` reads one issue body; `buildModel` derives the ready set, effective priority, serialize and together components, duplicate resolution and cycles from a set of them. Both are pure and total: neither throws on any input, and every anomaly becomes a diagnostic. At 0.1.0 the tokenizer is a hand-rolled restricted-subset reader with no runtime dependencies. That is an internal detail of a surface already pinned by tests, and it is being replaced: the tokenizer moves to an established frontmatter/YAML parser, with the key set exactly what the spec defines ([#6](https://github.com/autnmy/issuegraph/issues/6)). `isUnreadDeclaration` is the question a reader must ask before treating a declaration as complete — a dropped field leaves `data` non-null and looking finished.
- **`@issuegraph/writer` 0.1.0** — the three ways a block gets written. `renderFrontmatter` emits a fresh one; `spliceGeneratedEdges` refreshes only the edges one writer owns and leaves every other byte alone, including author metadata the format makes inert; `backfillFrontmatter` repairs a block a code fence left undelimited by adding the `---` pair its author omitted and changing nothing else. Reading and writing have opposite error disciplines on purpose: a parser takes untrusted issue text and never throws, a writer takes its caller's own data and throws before it can file an issue whose graph lies.
  - **The round-trip is pinned ACROSS the package boundary.** `parseFrontmatter(renderFrontmatter(x))` is asserted against `expectedParseOfRender(x)` from inside the writer's own suite, so a spelling that drifts on either side fails rather than being caught by whichever package happened to own both halves.
  - **Ownership is per-field and opt-in.** An omitted field is untouched — round-tripping parsed values back through a splice would launder away exotic spellings and unparseable items the parser tolerates with a diagnostic, so omission is the honest "not mine" signal. What a PRESENT `null` means is not uniform: on the scheduling edges (`blockedBy`, `serializeWith`) it removes, while on `decomposedFrom` and `duplicateOf` it also leaves the value alone, because the established caller shape there is "write it when the block lacks one, never clobber one that is already there" and such a caller passes `null` to mean exactly that. So those two cannot currently be CLEARED through a splice; the gap is stated rather than closed by overloading a value that already has a caller.
  - **The backfill preserves rather than re-spells.** Re-rendering from the parsed value is lossy by construction — a renderer emits only what the parser models — and it deleted rejected field values, inert extension fields and YAML comments. It also repairs ONE shape: a block inside a code fence the walk can establish. An unfenced key is refused, because a fence is only one of the containers that make a column-zero key prose, and enumerating the rest grows a rule per review round.
- **`@issuegraph/reader` 0.2.0.** Two changes land in the same unreleased version — nothing publishes on a merge, so they share it rather than one of them claiming a version nobody can install.
  - **the line grammar is now shared, and a key-quoting defect is fixed.**
    - `locateBlock`, `topLevelKeyScalar`, `readMappingEntry`, `FENCE_OPEN` and `FENCE_CLOSE` are exported for `@issuegraph/writer`. An editor has to locate the same block, open the same section and recognise the same entries as the parser; spelling those rules twice is how a write hands back a body its own parser cannot read.
    - **Fixes [#10](https://github.com/autnmy/issuegraph/issues/10).** `readMappingEntry` toggled quote state anywhere on the line, so a stray apostrophe in an ORDINARY key — `note's: x` — swallowed the colon and the line read as unparseable. An unparseable child is structural, so the whole block degraded and every real edge beside it was lost, over a field §4.1 says has no power at all. A quoted key must OPEN with its quote; anywhere else a quote is plain content. Escaped quotes (`''`, `\"`) are now tracked, so `'owner''s-note'` is one key.
    - The parse walk opens its section through `topLevelKeyScalar` rather than a second spelling of the same rule, so the predicate a writer locates a section by is the one the walk uses.
  - **`buildModel` gains an under-read tier.** `NodeInput` carries a **required** `declarationRead: 'read' | 'under-read'`, and the model acts on it: an under-read node is refused, so is any node sharing its `serialize-with` component (a dropped `serialize-with` means the component's true extent is unknown), and so is a node whose edge resolved to a CLOSED node that had itself been under-read — `blocked-by` and `together-with` both read the target's `open` flag to DISCHARGE the edge, and `targetKey` resolves that ref through the target's `duplicate-of`, so a dropped one reads the flag off the wrong node (a closed duplicate rather than a still-open canonical). `serialize-with` needs no such guard: it unions whatever the state, so closure discharges nothing there. Both shapes raise a diagnostic. `Model.underReadKeys` exposes the under-read set structurally, because one case is provably not the reader's to close: when the DROPPED FIELD IS ITSELF AN EDGE the peer's identity is what the parse destroyed, so the only sound refusal would be a global stall — that policy is the host's, and this is the seam for it. The package already shipped `isUnreadDeclaration` and a README insisting the question be asked — and then `buildModel` never asked it, so `blocked-by: [123, not-a-ref]` admitted a candidate gated on `#123` alone and `serialize-with: not-a-ref` admitted one that read exactly like a body declaring no relation. `data` alone cannot carry the answer, which is why the field is required rather than optional: an omission would compile. Effective priority is deliberately untouched — an under-read node under-reports a blocker's urgency, which reorders work but never admits any. **Breaking:** every producer must supply the field.
- **`@issuegraph/store` 0.1.0** — a client store for a document plus the data-source adapter port, so a host supplies its own tracker (BYO-DataSource) and the package fetches, authenticates and persists nothing.
  - **The order can be trusted.** Edits render optimistically; the selection order derives from **landed** edges alone, so an unlanded edit cannot move a ranking. While a write is in flight the order reports itself `held` and the previous rows stand.
  - **One authoritative operation at a time.** `hydrate` and an `applied` or `unchanged` `dispatch` all answer with a whole document, and the store runs one at a time — two unversioned snapshots in flight cannot be ordered, and the later answer arriving first silently rolls an edge back out.
  - **A failed write is marked, never reverted.** `failed` and `conflict` states; nothing auto-merges, auto-reverts or times out. A conflict's `upstream` is kept for view-diff and never adopted, so `discardMine` drops the overlay and `retry` re-dispatches; "retry on latest" is a host composition of `rehydrate()` + `retry()`, because the decisions across that await are about user intent.
  - **Refusals never reach the adapter.** Structural ones the store makes itself; graph-shaped ones come from an injected `EdgeGuard`. An injected deriver supplies the order — the store owns *when* it is recomputed, never *what* it is.
  - **A host cannot corrupt it by accident.** Every array reachable from a snapshot is frozen, copied first so an adapter is never frozen out of its own storage; every reused slice is compared structurally rather than field by field; and a deriver, guard or subscriber that throws cannot break the store or strand the queue.
  - **Two reference adapters.** An in-memory one a demo runs on with no backend at all, and a scripted asynchronous one that settles only when told to, so every failure arm can be induced rather than asserted.
- **`@issuegraph/derive` 0.1.0** — the selection order, one layer above the reader. `deriveIssueOrder` returns ranked slots, held slots carrying `rank: null` and the reasons they are held, together units collapsed to one slot, excluded duplicates, and priority promotions in the spec's own `P3 -> 0` notation; `wouldCycleOnBlockedBy` refuses a `blocked-by` edge that would close a cycle, synchronously and from data already in hand.
  - **The host's ranking is an input.** Whatever already orders a backlog — mapped labels, issue types, saved queries — is supplied, never re-derived, so the package does not become a second ordering engine beside the authoritative one. Frontmatter modifies that ranking rather than replacing it, which is what makes the package useful at zero adoption.
  - **These are the two ports `@issuegraph/store` declares and does not implement** — `OrderDeriver` and `EdgeGuard`. The store owns *when* the order is recomputed; this owns *what* it is.
  - **A held slot keeps its position.** "Why isn't my P1 running" is answerable at the rank the work would have taken; a claim-time selector that drops held work deletes exactly that information.
  - **Purity is pinned mechanically, not asserted.** The tests read the modules' own syntax tree for a dependency outside a four-entry allowlist and for module-scope mutable state, and pin reference identity and freshness so a memo returning the stored model fails — which a compare-by-value test alone would let through.
  - **Pinned against the reference prototype's own seed**, before and after its demonstration edit, so the two cannot drift.
  - **Duplicates resolve the model's way, and the two sites diverge on purpose.** An edge naming a duplicate names its canonical (§4.3.3), so both the cycle walk and the promotion provenance follow it — through `Model.duplicateCanonical`, never a second duplicate-chain walk. Where they differ: the cycle guard KEEPS an edge declared by a duplicate, because dropping one removes reachability and a cleared `duplicate-of` brings it back with the cycle already written; the provenance drops it, because an edge the model never read cannot be the reason it gives for a promotion.
  - **Both propagation paths, and both endpoint spellings.** Effective priority relaxes along `together-with` as well as `blocked-by` (§6.3), so promotion provenance reads both — a P3 grouped with a P0 is promoted and must say through whom, and the together half names the ADJACENT peer rather than the component (relaxation flattens a component to one priority, so enumerating it makes every member read as a cause). And the cycle probe resolves its own two arguments, not just the stored edges: each is walked under the key as given AND its canonical, because resolving only the stored side leaves the arguments in a different key space (a self-dependency goes unseen), while replacing the raw spelling would remove refusals a duplicate's own kept edges still earn.
  - **A slot's sizes describe the whole slot.** A together unit's serialize footprint is the union over its members' components, not the lead's — every member has to be free before the unit is admitted. Reading the lead alone made a structural number depend on the base ranking, since which member leads is a ranking outcome, so two clients ranking differently reported different sizes for one graph.
- **`@issuegraph/core`: `SYMMETRIC_EDGE_FIELDS` and `isSymmetricEdgeField`.** Which relationship kinds carry no direction (§4.3.4, §4.3.7) is format vocabulary, so it belongs with the rest of it rather than being rediscovered by each consumer that has to compare two edges.
- **`pnpm run ci` builds before it typechecks.** A package consuming another's published types cannot be typechecked until that one has emitted them, so on a fresh checkout the old order failed before it reached the build. Ordering it correctly is what makes a multi-package workspace check at all.
- **Import linting.** ESLint over `packages/` with `no-restricted-imports`, `import-x/no-absolute-path` and `import-x/no-relative-packages`. A real parser rather than a pattern, so template literals and comments are handled by construction. Each rule has a deliberate-violation test, and a control asserting the config matches the file.
- **Isolation guard.** `pnpm run check:isolation` refuses a forbidden dependency — by key, `npm:` alias target, or git URL — a relative import escaping its own package, and a consumer's brand token in any text a package ships, `package.json` metadata included. It scans by content rather than by an extension list, and does not exempt built output, because what a package can publish is an open set. Proved by tests that break each rule deliberately.
- **Version consistency.** SPEC.md §8 and the README both still said `v0.1.0` while the spec's own version header and this changelog said `0.2.0`. Corrected, and pinned by a test so the header and §8 cannot drift apart again.

## 0.2.0 — 2026-08-15

- §6.4 selection tiebreak: **newest first** is the default (was oldest first), with rationale — starvation avoidance now belongs to effective priority (an old issue that matters inherits urgency from its dependents), while recency buys premise freshness against issue-body rot. A deterministic executor-chosen tiebreak remains conformant.

## 0.1.0 — 2026-08-14

Initial draft.

- Carrier: standard YAML **frontmatter** on the issue body (`---`-delimited, top of body, never hidden), namespaced under a top-level `issuegraph` key. Nothing bespoke: the universal convention, on purpose.
- Fields: `blocked-by`, `decomposed-from`, `duplicate-of`, `serialize-with`, `together-with`, `priority`, `evidence`.
- No container issues: `decomposed-from` is provenance; tracking issues are replaced by queries; whole-feature gates are ordinary issues blocked by their siblings.
- `serialize-with` groups (connected components, width-1 semaphore, claim-time direction) and `together-with` units (group readiness over boundary-crossing edges, atomic claim, max effective priority, individual closure). The coordination vocabulary is closed at these two; preference fields are rejected.
- Scalar carrier precedence: established tracker conventions (priority labels, an evidence label pair) are canonical over the frontmatter; relationship fields are frontmatter-canonical.
- Writing rules bind every writer; the size rule; closure semantics (any closure unblocks, non-completed closure flags dependents for re-groom); the decision-issue pattern for nameable human gates; holds as executor policy composed via ready-and-eligible selection.
- Reading rules: ready set, backward-flowing effective priority, oldest-first tiebreak, detect-on-read cycles, fail-safe unresolvable references.
- Scope rule: the format describes work, never execution.
